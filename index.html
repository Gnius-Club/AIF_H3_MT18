Todo lo que necesitas para preparar y ejecutar esta misión en minutos.

🎯 Objetivo de Aprendizaje

Comprender el diagnóstico basado en evidencia y la precisión comunicativa. Usar WebWave y JDoodle para ejecutar un diagnóstico full-stack mediante la inspección de request/response.

🤖 Prompt de Referencia para XOLO (Solo para Maestro)

⚠️ NOTA: XOLO ya conoce el tema de esta misión. Este prompt es SOLO de referencia en caso de emergencia técnica: 
Explícame cómo ejecutar el diagnóstico full-stack en práctica: reproducir el error, observar Network, inspeccionar request/response y comparar con lo esperado. Analicemos cómo redactar una oración de diagnóstico que sea precisa y verificable, sin suposiciones. Guíame para localizar si el problema está en frontend (manejo/parseo) o backend (formato/datos/status).

⚡ Puntos Esenciales de la Misión

🎓

Concepto Clave

Diagnóstico basado en evidencia: Es como ser un detective que solo acusa basándose en huellas digitales y fotos, no en sospechas, asegurando que cada falla encontrada tenga una prueba clara.

🔧

Habilidad Técnica

Usar herramientas de inspección web para localizar fallas exactas en el intercambio de datos entre el navegador y el servidor.

🧪

Experimentación

Probar con diferentes tipos de errores (status 404 vs 500) para entender limitaciones de cada componente.

💬

Interacción con XOLO

XOLO ya conoce a cada estudiante y el tema de hoy. Solo abren el chat y comienzan a aprender. Tú guías el timing y motivación.

📊 Diapositiva 3: Brain Spark

1. 💬 Pide a XOLO que te ayude a crear:

"Ayúdame a resolver el caso como Cazador de Bugs con Vibe Coding: define conmigo qué evidencia necesito capturar (status, response body, formato). Luego, ayúdame a redactar mi oración final con el formato exacto del documento. Ejecuta: entrega el “Informe de Diagnóstico” (1 oración) y conserva un registro mínimo (captura o nota) de la evidencia que lo respalda."

2. 🔬 Experimenta y descubre con tu programa:

  • ¿Lograste reproducir el error de manera consistente?
  • ¿Qué pasa si cambias el formato de los datos en el request?
  • ¿Funciona igual el diagnóstico en el navegador que en el servidor?
  • Si encuentras un error, ¿cómo aseguras que tu diagnóstico se basa en evidencia y no en suposiciones?
  • ¿Por qué es vital la precisión comunicativa al explicarle a un compañero dónde está el bug?

¡Es hora de crear y cazar bugs! Vamos a pasar de la teoría a la acción. Usen el prompt en pantalla para que XOLO los guíe en la resolución de un caso real como 'Cazadores de Bugs'. El flujo es simple: ideen el caso, definan el VIBE, obtengan su GCS y llévenlo a WebWave o JDoodle. Por ejemplo, podrían simular un formulario que no envía datos y rastrear exactamente dónde se rompe la cadena. No olviden las preguntas de experimentación para profundizar. Si tienen errores o dudas, pregúntenle a XOLO, él los ayudará a depurar.
